# Model scope and provenance: provisional threat model

**Status:** design input, 13 September 2026, baseline `d2c69981eda797367e2222089ab2028ce63a179a`. This accompanies the [legal-source-registration decision report](LEGAL-SOURCE-REGISTRATION-DECISION-REPORT.md); neither document authorizes an implementation or says a Yuho model has been legally reviewed.

## Protected assets and trust boundaries

The assets are (1) exact source and executable-model bytes, (2) stable semantic IDs and byte-span mappings, (3) an inspectable positive scope and exclusions, (4) integrity-bound review statements, (5) the user's ability to distinguish technical kernel output from legal authority or adjudication, and (6) offline reproducibility. A digest protects comparison with *the digest supplied to the verifier*; it does not authenticate the person who supplied it. The current KernelInput source hash and span checks already protect local consistency within one request, as [the decoder](../../rewrite/haskell/src/Yuho/Protocol/Decode.hs) and [span validator](../../rewrite/haskell/src/Yuho/Core/Source.hs) show. The proposed bundle raises the comparison boundary to a whole model and its mapped source set; it cannot turn untrusted assertions into legal facts.

| Boundary | Inputs treated as untrusted | v1 control |
| --- | --- | --- |
| Network/catalog → package intake | URL, HTTP response, redirects, cache, publisher-looking host | No evaluation-time fetch; a safe offline package path and pinned raw-byte digest. A catalog entry is a locator only. |
| Package bytes → validator | JSON keys/types, paths, archives, media types, duplicate IDs, oversized blobs, cycles | Bounded closed decode, path containment, digest and reference checks before mapping/model load. No implicit extensions. |
| Source artifact → extracted text | HTML/PDF parser, character set, line endings, text order | Separate derived UTF-8 artifact and extraction recipe/digest; validate spans against **that** artifact. Human review of fidelity remains needed. |
| Source metadata → identity/authority | Citation, jurisdiction, publisher label, URL, dates | Store typed **assertions** with their stated origin; do not infer official publication, currentness or legal effect. |
| Semantic mapping → model | Modeller-selected ID, provision label, source span and declared role | Require complete ID inventory, source-backed spans or explicit synthetic exemption, exact scope/exclusions, whole-core digest. Correct interpretation remains review work. |
| Review record → reviewer identity | Name, email, role, organisation, checklist result, timestamp | Bind review subject to bundle/scope digest; label unsigned records `identity_unverified`. Signature/credential and trust policy deferred. |
| Bundle → kernel/user | Selected bundle, case facts, request date, UI wording | Keep seven KernelInput variants unchanged and return technical judgments only. Package validation never becomes a negative legal result. |

Potential adversaries include an attacker replacing hosted source bytes, a malicious model author supplying plausible citations, a compromised artifact store or credential, and an operator selecting the wrong version. Accidental failures include stale consolidations, missing amendments, broken extraction, partial mapping, incorrect date labels, unqualified review, scope creep in product copy and review records left attached after a model change. None requires an attacker to forge SHA-256: a coherent but false assertion can be hashed perfectly.

## Failure/disposition matrix

`Reject` means do not execute this package as a validated source-backed model. `Record` means preserve a clearly labelled assertion or limitation, not semantic `unresolved`. `Policy` means a later explicit institutional/legal rule must decide. These are proposed package-validator outcomes, separate from existing kernel diagnostic codes.

| Failure or attack | v1 disposition and mitigation | Residual risk / deferred control |
| --- | --- | --- |
| A source URL serves changed bytes, disappears or redirects | **Reject** a fetched blob whose bytes differ from pinned digest; offline evaluation uses stored bytes and does not fetch. Record locator outage. | Correct digest may refer to a now-superseded version; update service and review policy needed. |
| Malicious or mistaken source label; unofficial mirror described as official | **Record untrusted assertion**; display actual artifact digest and claimed origin distinctly. Unsupported `verified_official` flag **rejects**. | Publisher authentication and evidence of official publication deferred. |
| Valid digest attached to wrong Act, judgment or expression | Structural checks pass; **record as unverified identity assertion**, require human/policy check before legal use. | Hash cannot prove the work/expression association. |
| Stale consolidated legislation, omitted amendment, incorrect effective/commencement date | **Record limitation/untrusted temporal assertion**; reject impossible or internally contradictory typed dates, but do not infer point-in-time applicability. | Jurisdiction-specific change-monitoring, as-published and commencement review required. SSO [FAQ B1–B10](https://sso.agc.gov.sg/FAQ) distinguishes the Gazette's published text from informal consolidation and explains timelines/commencement. |
| Incomplete source-to-rule mapping or missing artifact | **Reject** unmapped executable ID, missing required artifact/span or scope ID mismatch, except an enumerated synthetic/internal exemption; explicit excluded legal units remain outside positive coverage. | Human may still find an interpretation incomplete despite every ID having a span. |
| Partially reviewed model presented as complete | **Reject** `complete_instrument` as unsupported; scope must be `enumerated_only`. A review narrower than a requested use is **incomplete**, not approval. | Scope descriptions may misstate what's legally required; legal review needed. |
| Review record survives a source, model, mapping or critical metadata change | **Reject subject match** because bundle/scope digest changes; preserve historical record for old digest only. | A reviewer can still sign off on wrong bytes or a falsely described scope. |
| Duplicate/conflicting review records | **Record both** in stable order; identical review ID with different bytes **rejects**; do not select a favorable outcome automatically. | External policy must decide quorum, supersession, qualification and revocation. |
| Compromised signing key; authenticated but unqualified reviewer | Signatures not accepted as trust in v1; **defer to policy** even if later crypto verifies. | Credential revocation, role/qualification and purpose policy required. |
| Authoritative source modeled incorrectly | Digest/mapping may pass; **legal uncertainty** requires independent model-fidelity review and counterexamples. | No hash, signature or formal proof of the technical algebra establishes legal fidelity. |
| Correct model applied outside jurisdiction or temporal scope | **Record/expose scope and request mismatch**; initial package layer must not declare applicability from date comparison. An application that asserts coverage outside positive scope must **reject that claim**. | Case-specific jurisdiction, transitions and conflicts require reviewed law. |
| Parser span drift or non-deterministic extraction | **Reject** invalid byte offsets/boundaries, recipe mismatch or output digest mismatch; require byte-identical extraction replay fixtures. | Span may still point to semantically wrong but valid text; reviewer checks mapping. |
| Unsupported/proprietary media type | **Capability reject** as executable mapped text; may retain non-executable opaque reference only if explicitly declared and bounded. | Fidelity of external viewer/extractor unknown. |
| Duplicate artifact digest, missing blob, path traversal, symlink escape, archive bomb, oversized input | Deduplicate identical bytes by digest; conflicting ID/digest mapping, missing blob or unsafe path **reject**; enforce proposed byte/count/depth limits before parsing/decompression. | Limits need empirical tuning on legitimate packages. |
| Cyclic `derived_from` or metadata references | **Reject** before traversal; validation order and cycle witness deterministic. | Real document relationships may be non-tree; only typed acyclic *artifact derivation* is constrained. |
| An absent online source during offline execution | **No runtime failure** when package has pinned bytes; record external freshness/authenticity as unverified. | Offline execution cannot check current publication or revocation. |
| An issuer/reviewer label is treated as credential or a source hash as court approval | **Prohibit claim** in schema/UI/test wording; labels and hashes remain explicitly descriptive/integrity-only. | Misuse by downstream consumers remains possible; documentation and policy audits needed. |

Some dispositions depend on *claim type*: a partial bundle is structurally valid when it openly lists a narrow positive scope; it is **not** valid evidence for whole-Act coverage. A conflicting metadata assertion is preserved for review if it is merely competing descriptive information, but a single source record with two incompatible identities under one unique key rejects. Package failures must not become a valid kernel `not_satisfied`, `false` or semantic `unresolved` result.

## v1 mitigations, deferred controls and claims

The recommended v1 core uses raw-byte SHA-256 per artifact, a separately versioned domain-separated core digest, deterministic JSON under a pinned canonicalization profile, bounded closed objects, exact semantic-ID inventory, UTF-8 span and source-order checks, explicit omissions and dependencies, and detached review subjects matched by digest. The [decision report](LEGAL-SOURCE-REGISTRATION-DECISION-REPORT.md) proposes a single SHA-256 profile and an explicit `yuho.model-bundle/v1\0` separator; Canonical IR v1.2 and current KernelInput hashes are untouched. The bundle should be usable without network access. A changed source artifact must be repackaged under a freshly computed digest and core digest; retain old packages for reproducibility.

Deferred: verified publisher acquisition, signed [in-toto v1 statements](https://github.com/in-toto/attestation/blob/v1.0/spec/v1.0/statement.md) or equivalent, key rotation/revocation, authenticated reviewer registry, trusted organisational roles, jurisdiction-specific source hierarchy, point-in-time applicability resolver, amendment completeness checking, review renewal rules and legally reviewed model fidelity. A future signature verification step proves only that a particular credential signed exact bytes; a trust root/policy must decide whose credential it is and what claims that person may make. An authenticated source can still be modeled wrongly. An authenticated but unqualified reviewer is not sufficient. [PROV-O](https://www.w3.org/TR/prov-o/) lineage is useful for traceability, not authentication.

**Prohibited v1 claims:** “official source verified,” “authoritative legal text,” “legally current,” “complete Penal Code model,” “certified by counsel,” “reviewer identity verified,” “court-approved,” “legally applicable,” “legally correct,” “conviction,” “acquittal,” or “recommended sentence” on the strength of a package hash, unsigned review, source label or existing kernel result. Narrow accurate claims are “artifact bytes match recorded SHA-256,” “mapping spans fit these bytes,” “positive scope enumerates these semantic IDs,” and “this unsigned review record names this exact bundle digest.” The same caution applies to the [criminal-outcome boundary](CRIMINAL-OUTCOME-BOUNDARY-DECISION-REPORT.md).

## Test and operational requirements before implementation

Test cross-language canonical bytes and domain separation; byte changes to source, mapping, semantic object, scope or critical metadata must change core digest and invalidate old review subject matching. Include adversarial duplicate keys/IDs, Unicode normalization lookalikes, CRLF/LF variants, zero-width text, invalid UTF-8, large integers, path traversal, symlinks, archive bombs, resource limits, unsupported media, missing blobs, collisions of local/external IDs, contradictory dates, mapping to wrong but in-bounds passage, and source-order preservation. The in-bounds-wrong-passage case should **pass structural checks but fail human review**, explicitly showing the assurance limit. Test a changed URL that returns a new digest; a different official-looking URL with identical bytes; two manifestations of one asserted expression; two expressions of one work; an extracted-text transform whose output differs between runs; unsigned, expired, superseded and conflicting review records; and offline evaluation with dead locators. Do not weaken seven-fragment goldens or Canonical IR v1.2 hash fixtures.

Operationally, keep an append-only package history and a separate mutable discovery/revocation feed that never rewrites a content-addressed core. A newly published amendment, SSO correction, eLitigation editorial correction or reviewer revocation creates a new assertion/package/review event. Consumers must display the exact digest, scope, review subject and trust state they used; a cached validation result is keyed by digest and validator/profile version. A stale review remains historical evidence about its original bytes but is not transplanted to a replacement package. If a publisher or source is unreachable, offline use can be reproducible, yet its current authority and currency remain unverified. A separate policy must specify whether such a package may be used for research, editorial drafting or any higher-stakes deployment.
