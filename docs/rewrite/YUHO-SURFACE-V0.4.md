# YuhoSurface-v0.4: synthetic typed execution plans

**Status:** bounded fictional compiler and kernel conformance subset, 14 September 2026. The [plan parser and runner](../../rewrite/frontend/plan.py) use the existing [shared lexer](../../rewrite/frontend/core.py), [v0.2 resolver](../../rewrite/frontend/modules.py), [CLI](../../rewrite/frontend/__main__.py), Haskell kernel and ModelBundle-v1 validator. Orchestration does not turn a technical fragment result into a judicial decision.

## Authored language and typed bridge

The [fictional plan](../../rewrite/frontend/fixtures/plan/plan.yh) declares four explicit steps. Its first references an authored [offence-plus-exception composition](../../rewrite/frontend/fixtures/plan/proof/composition.yh). The others reference authored [candidate-selection](../../rewrite/frontend/fixtures/plan/fragments/fictional.candidate-selection.yh), [basic-term](../../rewrite/frontend/fixtures/plan/fragments/fictional.basic-terms.yh) and [enhanced-term](../../rewrite/frontend/fixtures/plan/fragments/fictional.enhanced-terms.yh) models. A separate [scenario](../../rewrite/frontend/fixtures/plan/scenarios/basic.yh) supplies proof classifications and Boolean inputs. Importing or resolving a model alone never executes it.

The proof-to-choice bridge reads the registered root status from SuppliedProofStatus-v1. Only exact satisfied opens the choice step; not_satisfied with branch reason defeated records upstream_defeated, unmet requirements record upstream_not_proved, and unresolved records upstream_unresolved. Those skip reasons propagate to terms steps without fabricating an intermediate candidate result. Proof-status observations remain separate from the technical gate; no legal or factual proof is inferred. GuardedPenaltySelection-v1 returns a set of exact candidate declaration IDs, not a sentence. More than one selected candidate is an ambiguous-route failure. Two static PenaltyTerms-v1 requests are gated on membership of exact pen:basic or pen:enhanced and each result is checked against its own authored declaration and term. No cross-fragment fact or identifier coercion occurs.

The compiler accepts only the four roles and three existing variants in this fixture. It compiles every request, checks source/model/scenario references, constructs and independently validates four ordinary ModelBundle-v1 directories, and checks computed digests **before** the first kernel call. Dependencies form a finite DAG; ready steps are ordered by step ID. Skipped steps have no fabricated response. A successful kernel response can have a domain unresolved state. Process, protocol, hash, bundle or routing failures abort the plan and emit a structured diagnostic, not a successful trace.

## Canonical records, CLI and limits

The [yuho.execution-plan/v0.1 schema](../../rewrite/frontend/schema/execution-plan-v0.1.schema.json) describes compact sorted-key UTF-8 JSON without a final newline. It records plan identity/version, fictional scope, topologically ordered typed steps, exact request SHA-256 and independently validated step-bundle digest, dependency, registered gate, outputs and limits. The separate yuho.execution-module-lock/v0.1 record binds plan and all six model-module source byte lengths and SHA-256 values. The [yuho.execution-trace/v0.1 schema](../../rewrite/frontend/schema/execution-trace-v0.1.schema.json) describes the record binding plan hash, lock hash and exact scenario bytes; it records deterministic step order, gate evaluations, state, request/bundle/response hashes, registered technical outputs and skip reasons, and exposes only four declared technical outputs. The choice step retains the kernel's selected-ID set and its technical true/false/unresolved status separately. None contains timestamps, absolute paths, host/user identity, source-authentication claims or judicial outcomes. These are external plan records, **not** one ModelBundle-v1.

The fixed v0.4 limits are four steps, three dependency edges, four exposed outputs, 64 KiB per Yuho source, 1 MiB per request, 4 MiB per response, 4 MiB aggregate request bytes and 8 MiB aggregate response bytes. The v0.2 proof resolver also limits module count, depth and aggregate source bytes. The runner uses a 30-second process timeout and a response-file size cap. It rejects duplicate IDs, unsupported variants, unknown/unregistered outputs, incompatible gate operands, cycles, unsafe paths, ambiguous candidates, invalid assignments and mismatched hashes. SFE052–SFE067 cover this bounded plan layer; earlier SFE001–SFE051 retain their meanings.

From the repository root after an offline Haskell build:

    ROOT=rewrite/frontend/fixtures/plan
    OUT=$(mktemp -d)
    python3 -m rewrite.frontend plan-check "$ROOT/plan.yh" --module-root "$ROOT" --scenario "$ROOT/scenarios/basic.yh"
    python3 -m rewrite.frontend plan-run "$ROOT/plan.yh" --module-root "$ROOT" --scenario "$ROOT/scenarios/basic.yh" --trace-output "$OUT/trace.json" --plan-output "$OUT/plan.json" --lock-output "$OUT/lock.json" --kernel-bin "$(cd rewrite/haskell && cabal list-bin exe:yuho-kernel)" --bundle-bin "$(cd rewrite/haskell && cabal list-bin exe:yuho-model-bundle)"

Plan-check writes no outputs. Plan-run prints one machine-readable status line, publishes canonical records to distinct new paths with rollback if publication fails, and leaves no successful trace on failure. Stderr diagnostics are canonical JSON with SFE code, path, line and byte column. Step bundles are ordinary ModelBundle-v1 packages; the plan is an external packet binding their digests. The existing bundle format has no multi-step-plan role.

The fictional term models use the kernel's closed nominal term_imprisonment/days vocabulary, with one- and two-day synthetic bounds. That schema-compatible technical description neither calculates nor imposes a sentence. No real legislation, legal applicability, evidence assessment, diagnosis, liability, guilt, conviction, acquittal, judicial disposition, dynamic sentencing, arbitrary scripting, network import, loop or retroactive operation is supported. Canonical IR v1.2 and all seven kernel variants remain unchanged.

The [decision-covering test](../../rewrite/frontend/test/test_plan.py) uses seven authored-scenario variations: basic selected; enhanced selected; exception defeat; offence requirements not proved; proof unresolved; selection eligibility false; and no candidate selected. It also rejects simultaneous basic/enhanced selection rather than choosing a winner. A valid GuardedPenaltySelection-v1 wire request has total Boolean facts, so its unresolved selection branch is not reachable here; the runner keeps the status distinct if the protocol ever returns it successfully. The committed [basic plan](../../rewrite/frontend/fixtures/plan/snapshots/plan.json), [module lock](../../rewrite/frontend/fixtures/plan/snapshots/module-lock.json) and [technical trace](../../rewrite/frontend/fixtures/plan/snapshots/basic-trace.json) are intentional byte snapshots, changed only with an explicit fixture update and fresh validation.
