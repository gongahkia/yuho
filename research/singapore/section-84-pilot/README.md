# Section 84 offline source intake

This is a **pre-bundle source and representability packet**, not an executable Singapore-law model, a valid `ModelBundle-v1`, or legal advice. The [intake report](../../../docs/rewrite/SINGAPORE-SECTION-84-SOURCE-INTAKE-REPORT.md) records the observed pages, source limitations and review gates. The prior [decision report](../../../docs/rewrite/SINGAPORE-SECTION-84-PILOT-DECISION-REPORT.md) remains provisional.

The input directory contains three user-owned Firefox “Webpage, Complete” HTML snapshots and their `_files` directories. Do not edit or execute them. The extractor reads companion files only to compute a deterministic inventory; it never treats their scripts, styles or images as legislative text. It never uses the network. The committed [source lock](SOURCE-LOCK.json) contains exact source and generated-output hashes; these establish byte identity, not authenticity, legal authority, point-in-time applicability or model correctness.

From the repository root, set explicit directories and use the locked inspection timestamp:

```sh
python3 research/singapore/section-84-pilot/tools/extract_sources.py \
  --input-dir "$INTAKE_SOURCE_DIR" \
  --output-dir "$INTAKE_OUTPUT_DIR" \
  --inspection-timestamp 2026-09-13T05:02:05Z \
  --verify-lock research/singapore/section-84-pilot/SOURCE-LOCK.json
```

`INTAKE_SOURCE_DIR` is the immutable user-owned `sg-s84` capture directory; `INTAKE_OUTPUT_DIR` is a separate external generated directory. The tool rejects a nonempty output directory if its bytes differ. Generate into a new temporary directory to inspect any intentional change, then replace only outputs known to have been generated by this task. A new inspection timestamp deliberately changes the receipt and source lock. The lock is not regenerated implicitly.

The versioned `yuho.sg-legislation-html-extraction/v1` transform accepts only the three exact expected filenames, UTF-8 pages with matching saved URLs/titles, one active `div#legis`, and exact numbered `div.prov1` provisions. It extracts Penal Code s 84, Evidence Act s 107, and CPC ss 246–256C. It decodes HTML entities, inserts LF at structural rows/list cells, collapses whitespace *within* those lines to one ASCII space, drops blank lines and unrelated page content, and does not normalize Unicode. Extracted text is a new artifact, not the exact HTML bytes or an independently authenticated statutory expression. `EXTRACTION-MANIFEST.json` lists deliberate transformations and exclusions. Every generated text/JSON file ends in one LF; JSON is compact UTF-8 with sorted keys.

Limits: each HTML input 8 MiB; at most 100 companion files and 20 MiB combined companion bytes per act; each extracted text 2 MiB; each generated JSON file 2 MiB. An unsafe type, symlink, unexpected top-level entry, malformed UTF-8, wrong page, ambiguous version label, missing section, missing span anchor or limit breach rejects before output replacement. Companion assets are hashed but are not parsed or executed.

Run the focused synthetic and external regeneration tests with:

```sh
YUHO_S84_INPUT_DIR="$INTAKE_SOURCE_DIR" \
  PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s research/singapore/section-84-pilot/test -p 'test_*.py' -v
```

The external packet contains the receipt, manifest, span map, representability map, scope declaration and three extracted text files. The committed [representability summary](REPRESENTABILITY-SUMMARY.json) records classifications only; it has no fact assignments or executable request. The exact source-to-model, version, causation, burden and procedural questions remain for qualified review. `ModelBundle-v1` presently requires a complete executable-model artifact, so this packet cannot be validated or labelled as a ModelBundle. No source HTML or companion asset is committed.
